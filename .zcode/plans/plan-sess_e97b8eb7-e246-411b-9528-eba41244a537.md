# Фикс: шаттлы появляются в проверенном пустом пространстве

## Context

Все шаттлы у станции (карго, ивентовые, ЦК-правила, фолбэки эвака/arrivals) размещает общий метод `TryGetFTLProximity`. Сейчас он делает до 32 случайных попыток на кольце 0–64 м от края станции; если ни одна не прошла валидацию `IsFTLTargetCoordinatesValid` (пересечение с гридами, exclusion-зоны, границы планеты) — метод возвращает `false`, и шаттл либо молча исчезает вместе с картой-пустышкой (`CargoSpawn`, `TryGridSpawn`), либо ивент целиком удаляется (`LoadMapRuleSystem`). Эвакуационный шаттл дополнительно грузится на карту ЦК на фиксированный офсет (500+индекс, 0) без какой-либо проверки занятости.

Цель: шаттл всегда появляется в **проверенно пустом** месте — поиск расширяется наружу, пока не найдётся свободный участок, вместо отказа и удаления шаттла.

## Изменения

### 1. `Content.Server/Shuttles/Systems/ShuttleSystem.FasterThanLight.cs` — главное

**`TryGetFTLProximity` (L856–1007), блок выбора позиции (L960–997):** заменить одиночное кольцо попыток на прогрессивный многоступенчатый поиск:

- Кольцо 0 — текущее поведение без изменений: 32 попытки (`FTLProximityCandidateAttempts`) на радиусе `minRadius + [minOffset..maxOffset]` (0–64 м за край AABB), случайный угол; для «точечных» целей (пустой космос, `randomizePosition == false`) первая попытка — точно в целевую позицию, как в ваниле (важно для генерации данжей).
- Кольца 1..N (новая константа `FTLProximityFarRings = 3`, множитель 2f): те же случайные попытки, но `maxOffset` масштабируется ×2, ×4, ×8 (до ~512 м), по ~16 попыток на кольцо. Все кандидаты по-прежнему проходят полную валидацию `IsFTLTargetCoordinatesValid`.
- Существующий фолбэк на `targetCoordinates` (L999–1004) сохранить.

Итог: шаттл садится в ближайшее проверенно пустое место; отказ возможен только если вся окрестность радиусом ~0.5 км забита гридами.

**`IsFTLTargetCoordinatesValid` (L1009):** сделать `public`, чтобы переиспользовать проверку в EmergencyShuttleSystem.

### 2. `Content.Server/Shuttles/Systems/ShuttleSystem.GridFill.cs` — шаттл не исчезает молча

- `CargoSpawn` (L70–76): вызов `TryFTLProximity` проверить; при неудаче — `Log.Error` + `DeleteEntity(ent.Value)` и **не** добавлять грид станции (сейчас грид остаётся на удаляемой карте-пустышке, но станция уже получила ссылку).
- `TryGridSpawn` (L139–152): при неудаче `TryFTLProximity` — `Log.Error` + `DeleteEntity(grid.Value)` + `return false` (сейчас грид молча умирает вместе с dummy-картой в `GridSpawns`).

### 3. `Content.Server/GameTicking/Rules/LoadMapRuleSystem.cs` — ивентовый шаттл не удаляется

Блок DS14 (L102–128): при неудаче relocated-поиска не удалять гриды/карту и не убивать правило (`ForceEndSelf`), а оставить шаттл(ы) на собственной загруженной карте (как обычные ивенты) с `Log.Warning`. Провал после фикса №1 практически невозможен, но теперь деградация мягкая.

### 4. `Content.Server/Shuttles/Systems/EmergencyShuttleSystem.cs` — эвакуационные шаттлы на карте ЦК

`AddEmergencyShuttle` (~L584–641): после `TryLoadGrid` на офсете `(500 + ShuttleIndex, 0)` проверить место публичным `IsFTLTargetCoordinatesValid(shuttle, координаты, Angle.Zero)`; пока место занято (структуры ЦК или чужие шаттлы) — увеличивать `ShuttleIndex` на `LocalAABB.Width + ShuttleSpawnBuffer`, переносить шаттл `SetCoordinates` и перепроверять (лимит ~20 итераций). Проверка уже корректно исключает сам шаттл.

## Не трогаем

- `TryGetExpeditionLandingSpot` / `Smimsh` (посадка на экспедициях) — свой механизм, недавно чинился (коммит e68e770a82).
- Фолбэк запуска эвака `NextVector2(1000f)` в `EmergencyShuttleSystem.Console.cs` — экстренный путь без карты ЦК, вне скоупа.

## Проверка

1. `dotnet build SpaceStation14.slnx -c Debug` — сборка без ошибок.
2. Прогнать существующие тесты шаттлов, если затрагиваются: `dotnet test Content.Tests` (быстро отфильтровать по Shuttle).
3. Ручная проверка (опционально): поднять локальный сервер (`runserver-Tools.bat`), старт раунда — карго-шаттл появляется в чистом космосе возле станции; через `/addgamerule` ЦК-ивент — шаттл ивента появляется у станции, а не удаляется.
